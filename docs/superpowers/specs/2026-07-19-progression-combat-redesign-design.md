# 暗影机械城 · 成长与战斗系统重构设计

日期：2026-07-19  
状态：已完成对话设计确认，等待用户审阅书面规格

## 1. 目标与边界

本轮把旧的列表式技能面板、基础背包界面、同质化敌人行为和分散的命中反馈升级为可持续扩展的商业 Demo 基线。实施拆成四个可独立测试、提交和发布的交付包：

1. **13A 成长界面与统一属性**：技能树、背包装备、存档迁移和统一属性聚合。
2. **13B 武器家族与组合技能**：完善现有武器，并新增双刀、长枪、弓弩装备及其技能变体。
3. **13C 敌人职责与进攻编排**：扩展敌人状态、职责、攻击令牌和房间组合。
4. **13D 打击感统一**：命中停顿、硬直、击退、材质音效、镜头与特效分层。

阶段 11 的机器人、量子升级、黑客和量子空间仍保持延后，不借本轮提前实现。本轮不删除旧装备、技能等级、探索能力或已获得武器。

## 2. 共同架构

技能、装备、玩家、HUD 和战斗公式读取同一个最终属性快照：

`角色基础属性 + 技能修正 + 装备修正 + 临时状态 = 最终战斗属性`

统一修正键至少包含：

- `attack_flat`、`attack_percent`
- `crit_chance`、`crit_damage`
- `max_health`、`armor`
- `move_speed`、`stagger_power`
- `skill_damage`、`cooldown_rate`
- `max_mp`、`mp_regen`

界面只展示属性快照，不直接改玩家变量；战斗计算也只消费快照。技能树、装备词条和临时增益各自产生修正字典，由单一聚合器按固定顺序合并。这样 UI 对比与实际伤害不会出现两套结果。

## 3. 技能系统

### 3.1 页面结构

全屏技能界面顶部提供四页：

- **基础**：生命、技力、回复、暴击、防御和资源效率。
- **身法**：冲刺、空中控制、墙面动作、滑翔、冲刺反击。
- **战斗**：先选择武器家族，再进入该家族技能树。
- **探索**：炸弹、攀墙、水下推进、滑翔和暗影滑翔翼的取得后强化。

探索能力本体仍由关卡道具获得；技能点只能强化已取得能力，不能提前绕过区域门控。冲刺、跳跃和已有基础移动不会因迁移重新锁定。

### 3.2 战斗武器家族

- **刀剑**：快速连段、剑气、格挡反击、突进斩、终结技。
- **铁锤**：蓄力、霸体、震地、破甲、范围控制。
- **蒸汽枪炮**：弹药、散射、贯穿、后跃射击、过载炮。
- **双刀**：高速连击、标记、闪身追击、交叉处决。
- **长枪**：中距离控制、蓄力突刺、挑空、招架反击、冲锋。
- **弓弩**：蓄力瞄准、弱点、穿透箭、爆裂弩、陷阱、箭雨。

当前铁剑、重锤、蒸汽炮、遗迹大剑、虚空之刃和腐化镰刀映射到明确家族。双刀、长枪和弓弩由 13B 添加真实装备数据、获取方式、普攻动作、重攻击和主动技能变体；在装备实际进入游戏前，其分支显示锁定来源，不能投入技能点。

### 3.3 节点视觉与导航

技能节点使用圆形机械芯片：

- 未解锁：暗灰核心与断开的连接线。
- 可学习：低频呼吸光圈。
- 已学习：实心能量环。
- 当前选择：双层高亮圆环与旋转刻度。
- 满级：金色核心。
- 前置不足：右侧列出缺少的节点、等级、武器或探索能力。

鼠标悬停、鼠标点击、键盘和手柄共用单一选中状态。四向导航根据节点屏幕坐标，在对应半平面内按方向夹角和距离寻找最近节点，不依赖控件创建顺序。切页后恢复该页上次选择；首次打开选择根节点。

### 3.4 详情、动画和教学

右侧详情区固定包含：

1. 当前武器与技能的角色动画循环预览。
2. 技能名称、等级、类型和实际数值变化。
3. 输入方式，例如 `J → J → ↑K`。
4. 前置招式、可衔接技能、取消窗口、空中/地面限制。
5. 技力、怒气、冷却、霸体和无敌帧信息。
6. 武器适配及切换武器后的技能变形。
7. 实战用途，例如破甲、对空、追击、脱离或控场。

组合技能以连接节点表示，组成招式均已学习后才可解锁。详情区显示简化连招图，不要求玩家从描述中猜输入。

被动技能也必须提供“如何使用”：明确触发条件、生效时机、适合场景和可见反馈。例如“完美格挡后自动触发，持续 2 秒，角色外圈出现蓝色齿轮环”，不得只写“伤害 +10%”。

动画预览复用玩家实际动作和武器表现，通过独立 SubViewport/预览控制器播放，不使用与实战无关的装饰动画；预览不修改存档、不消耗资源、不产生世界碰撞。

## 4. 背包与装备

### 4.1 三栏布局

- **左栏**：角色展示与头部、胸甲、手套、靴子、饰品、武器槽。装备变化立即刷新展示和属性。
- **中栏**：武器、防具、饰品、消耗品、材料、任务道具六类仓库。方格显示图标、稀有度、强化等级、数量和新获得标记。
- **右栏**：名称、说明、基础属性、随机词条、强化效果、套装效果、来源和当前装备对比。

属性对比以“当前 → 候选”显示；提升为绿色，下降为红色，无法比较的功能性词条使用中性紫色。键盘/手柄四向导航与鼠标选择共享状态。底部保留快捷消耗栏和容量信息，本轮不增加会阻塞探索的负重惩罚。

### 4.2 数据与操作

保留现有装备 ID、稀有度、强化等级、随机词条和装备槽。排序至少支持类别、稀有度、强化等级和获得顺序。装备、卸下、使用消耗品和丢弃操作必须有明确焦点与确认反馈；任务道具和唯一武器不可丢弃。

角色展示优先复用实际玩家精灵、武器挂点和装备色调；若某装备没有独立外观资源，则显示槽位图标和属性变化，不能用固定角色宣传图冒充实时换装。

## 5. 存档兼容

新增存档版本号和幂等迁移函数：同一存档重复加载不会重复发放或重复加点。

- 旧技能 ID 映射到新节点 ID，等级不丢失。
- 旧装备与词条原样保留，新增字段使用安全默认值。
- 已获得探索能力和武器继续保持解锁。
- 无法识别的数据保存在兼容字典中并记录警告，不覆盖原始值。
- 迁移异常时使用旧数据构建保守快照，不保存半迁移状态。

自动测试使用旧版本存档夹具验证技能点总量、装备数量、能力和武器集合在迁移前后保持一致。

## 6. 敌人职责与进攻多样性

敌人以职责而不是贴图区分：

- **压迫型**：追击、冲锋、短连击，迫使玩家移动。
- **防守型**：格挡、盾反、霸体，需要破防、绕后或重击。
- **远程型**：预判射击、扇形弹幕、落点封锁。
- **空中型**：巡航、俯冲、投射、撤离，不停驻在固定高度反复单招。
- **控制型**：减速、牵引、地雷、风场、治疗或护盾。
- **指挥精英**：强化附近敌人并切换小队进攻节奏。

近战强攻动作受房间级攻击令牌约束；普通难度同时强攻者有限，其余敌人执行包围、压迫或准备动作。远程封锁和空中俯冲使用独立预算，避免所有敌人同时贴脸，也避免全员在远处等待。

房间配置按职责组合，并根据区域主题赋予变体。每种攻击必须有可辨起手、危险区或声音提示；高速不可反应攻击不与屏外生成同时出现。

## 7. 打击感标准

- **轻武器**：短命中停顿、快速刀光、低幅镜头震动、连续音高变化。
- **重武器**：明显蓄力、较长命中停顿、强击退、地面震动和低频命中层。
- **枪炮/弓弩**：后坐力、枪口/弩机反馈、弹道尾迹、命中爆点和环境回声。
- **完美格挡、暴击、破甲、击杀**：使用不同颜色、音效、停顿和镜头强度，不能共用同一闪光替代。
- **敌人受击**：按韧性进入闪白、轻硬直、重硬直、击退、破甲和死亡反应；Boss 仅在允许窗口进入硬直。

打击反馈由集中配置表定义，攻击只提交命中上下文（武器家族、伤害、暴击、破甲、目标材质、是否击杀），反馈系统据此播放停顿、震屏、特效和音频。设置菜单中的震屏强度必须继续生效。

## 8. 错误处理与可测试性

- 技能或装备引用未知 ID 时显示安全占位名称并记录错误，不让界面崩溃。
- 节点图检测重复 ID、缺失前置、循环依赖、越界等级和无效武器家族。
- 属性聚合器使用纯函数测试，UI 不作为数值真相来源。
- 敌人攻击令牌在敌人死亡、退场、换房和异常中断时必须释放。
- 预览 SubViewport 与战斗世界隔离，关闭面板时停止处理和音频。

每个交付包必须执行：对应契约测试、全项目脚本解析、完整 `ERROR / SCRIPT ERROR` 扫描、godot-capture 实际 PNG/动作连拍目视检查、`docs/qa/` 验收报告、DEV_PLAN 更新、源码 Godot Release 导出和发布包本体验证。

## 9. 实施分解与验收结果

### 13A 成长界面与统一属性

交付四页圆形技能树、三栏背包、统一属性快照和旧存档迁移。验收要求鼠标与键盘四向导航一致，详情区显示组合/被动教学，装备对比数值与实际玩家属性相同。

### 13B 武器家族与组合技能

交付双刀、长枪、弓弩真实装备及获取方式、普攻/重击/主动技能、动画预览和组合节点。验收要求三种武器均能获得、装备、切换、造成伤害并完成至少一条组合技。

### 13C 敌人职责与进攻编排

每个职责至少交付一种可运行行为，并在三个不同区域构造混合小队房间。验收要求攻击令牌限制生效、攻击起手可读、空中与远程敌人不再只循环单一动作。

### 13D 打击感统一

对刀剑、铁锤、枪炮、双刀、长枪和弓弩建立不同反馈配置；对格挡、暴击、破甲、击杀建立事件反馈。验收使用动作连拍检查形态差异，并保留人工试玩评估重量感、输入容错和数值平衡。

## 10. 素材与许可

新增素材优先使用项目已有授权资源、原创程序化图形或生成素材。下载素材仅接受明确允许商业使用的 CC0/等效许可来源，记录原始链接、作者、许可证和修改方式。不得直接复制参考商业游戏的角色、UI 图标、音效或动画资源。
