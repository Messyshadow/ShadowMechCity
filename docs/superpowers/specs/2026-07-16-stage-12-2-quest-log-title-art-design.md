# 阶段 12.2 主线任务、任务日志与标题主视觉设计

日期：2026-07-16

## 目标

在不破坏旧存档和既有按键的前提下，为现有七区域流程增加可追踪的主线任务链与任务日志；同时用一张原创暗黑机械城主视觉替换开始菜单的简易拉伸背景，让玩家能直接确认新版本已经发布。

## 设计选择

### 主线任务

采用纯数据定义与纯状态求值分离：`quest_data.gd` 只描述任务名称、叙事摘要、目标和下一任务；`quest_runtime.gd` 根据 `Game` 提供的世界快照计算锁定、进行中、可交付和完成状态。任务进度以已经访问的房间、已击败 Boss、已获得能力/武器以及叙事标记为事实来源，不复制战斗计数，从而兼容 10.1—10.8 旧存档。

首批主线分四章：

1. `echo_coordinates`「残响坐标」：与轨图解析师建立联系，进入废铁矿坑，击败岩核机甲巨兽。
2. `broken_network`「断裂的传送网」：肃清蒸汽铸造厂、腐化水道和遗迹神殿的区域 Boss。
3. `void_skyline`「越过虚空天幕」：进入虚空要塞并击败虚空天龙机甲。
4. `last_light`「最后的光核」：进入暗影王城并击败虚空机械君王。

完成前章后自动解锁后章；已有进度会在载入时即时回算，不要求玩家重复击杀。任务完成状态写入 `quest_flags`，用于通知、存档和后续 12.3 支线扩展。

### 任务日志与 HUD

- `N` 打开/关闭任务日志，不占用 `Q` 换武器及现有 `M/T/U` 菜单键。
- 左栏显示主线章节与状态，右栏显示任务名、摘要、逐项目标、区域提示和完成度。
- 鼠标点击、方向键/W/S、Enter 均可选择；当前项目使用青蓝圆环/边框高亮。
- HUD 右上区域标题下方显示当前追踪任务和最多两条未完成目标；日志可切换追踪任务。
- 打开日志时锁定玩家输入，但不暂停环境；关闭时恢复。
- 720p 下不遮挡底部操作提示，文本必须完整可读。

### 标题主视觉

生成一张无文字、无水印的 16:9 原创位图：暴雨与烟雾中的巨型暗黑机械城，铆接钢铁塔楼、齿轮、蒸汽管网、悬空轨道与深处虚空裂隙；青蓝虚空能量对比少量橙色炉火。中央偏左保留低细节暗区给中文标题和菜单，右侧承担视觉主体。使用 `TextureRect.STRETCH_KEEP_ASPECT_COVERED` 覆盖窗口，叠加暗角、扫描线/雾层和暗钢菜单板，避免不同分辨率拉伸。

生成资产记录为 OpenAI 内置图像生成工具生成、项目自有使用；无第三方素材或现成 IP 元素。

## 数据与存档

`Game` 新增 `quest_flags` 与 `tracked_quest_id`。存档缺少这些字段时迁移为空字典和首个未完成主线；无效追踪 ID 自动回退。任务快照至少包含 `visited`、`items`、`dialogue_flags`、`story_flags`、`unlocked_weapons`。

## 错误处理

- 未知任务或目标类型返回安全的锁定/未完成状态并报告清晰错误，不让 UI 崩溃。
- 标题背景资源加载失败时保留程序化暗色底层，不显示空白或粉色错误纹理。
- 任务面板在玩家、HUD 或任务数据尚未就绪时保持关闭。

## 验收

- 先运行失败契约，证明任务数据、运行时、存档字段、按键、面板与标题资产确实缺失。
- 新旧存档快照能正确回算四章状态；完成前章自动解锁后章。
- 编辑器全项目解析和 10.6.5、10.7、10.8、12.1、12.2 回归均通过。
- 使用 godot-capture 分别抓取标题页、任务日志、HUD 追踪器 PNG，并逐张检查主题、裁切、可读性与遮挡。
- 使用源码编译 Godot 和自定义 release 模板导出，再直接启动发布 EXE 扫描全部 `ERROR` / `SCRIPT ERROR`，从发布 EXE 再抓标题 PNG。
