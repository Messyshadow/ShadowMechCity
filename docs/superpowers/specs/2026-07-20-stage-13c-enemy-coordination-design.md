# 阶段 13C：敌人差异与同屏协同设计

日期：2026-07-20

## 目标

把“换色、换数值、共用冲锋”的现有敌人基线提升为可读、可应对的战斗角色，并让同屏敌人形成轮换进攻，而不是同时贴身或同时开火。本批聚焦已经进入主线后段、最能体现暗影机械/虚空主题的六类敌人：暗影机械鹰、虚空裂翼飞龙、虚空风暴法师机甲、王城铸魂盾卫、铸魂枪兵和铸魂炮手。

## 方案选择

1. **继续扩张单体分支**：只修改 `enemy.gd`，开发快，但每个敌人自行扫描同伴、计算冷却，规则会重复并互相冲突。
2. **共享调度器 + 角色策略（采用）**：每个房间一个轻量 `EnemyCombatDirector`，负责行动许可、远程错峰、站位槽和休整窗口；`enemy.gd` 保留通用移动/受击/死亡，只增加六种角色行为。
3. **每种敌人独立完整状态机**：隔离最好，但会复制碰撞、掉落、腐蚀和受击逻辑，超出 13C 单批范围。

采用方案 2。调度器不决定具体攻击，只决定“谁现在可以进攻”和“应占哪个相对站位”，敌人脚本仍拥有动作与特效，因此旧敌人不注册角色时完全沿用当前逻辑。

## 战斗调度器

新增 `scripts/enemy_combat_director.gd`，由 `main.gd` 在创建房间世界时实例化。公开职责：

- `register_enemy(enemy, role)` / `unregister_enemy(enemy)`：登记有效战斗角色并清理死亡引用。
- `request_action(enemy, channel, duration)`：`melee` 同时只允许一名近身压迫者，`ranged` 通过最小间隔错峰，`mobility` 允许飞行重新站位但不和该敌人自己的攻击重叠。
- `formation_offset(enemy, role)`：根据稳定登记顺序给出玩家两侧/上方的相对槽位，避免所有敌人挤在同一点。
- `notify_action_finished(enemy)`：提前释放令牌；超时令牌自动回收，避免敌人死亡后锁死战斗。

调度器只存在于当前房间，不写存档，不改变敌人掉落与房间完成条件。单个敌人时请求立即获得许可，保证旧关卡和独斗不被人为拖慢。

## 六类角色行为

### 虚空空战组

- **暗影机械鹰 / harrier**：在玩家斜上方巡弋；获得近战令牌后显示青色俯冲轨迹并高速掠过，攻击结束回到高位槽。未获令牌时保持侧上方，不反复贴脸。
- **虚空裂翼飞龙 / ambusher**：获得 mobility 许可后在玩家身后上方短距瞬移，生成三段残影；随后申请 ranged 许可，发射两枚交叉裂隙刃，再回到远侧高位。瞬移位置限制在房间可视战斗区附近，避免穿入地板。
- **虚空风暴法师 / controller**：保持远距悬浮，法术按受击阶段切换：未受击为单发追踪矛；累计 3 次受击后为三向扇形；累计 6 次后为五向旋涡。每次施法受远程错峰控制，法杖核心颜色和预警环对应当前法术。

### 王城地面组

- **铸魂盾卫 / vanguard**：占据玩家正面近槽；非攻击时进入面向防御姿态，正面受击减伤并以盾面火花反馈；获得近战令牌后使用短距盾击，负责逼迫位移。
- **铸魂枪兵 / lancer**：保持中距侧翼槽；取得近战令牌后先绘制品红贯穿线，再执行长距离突刺。不会与盾卫同时起手。
- **铸魂炮手 / artillery**：主动远离玩家，取得 ranged 许可后交替使用直射炮弹与三发弧形扇射；炮口蓄光先于弹体生成，给玩家明确反应窗口。

## 数据与兼容

`main.gd` 的敌人定义增加 `role` 字段，仅上述六种敌人设置。生成器把敌人真实类型和 role 传入通用脚本，并在加入场景树后交给调度器。其他现有敌人没有 role，继续使用原有行为；Boss、召唤物、存档格式、房间出口和击杀统计均不改变。

## 视觉与可读性

- 三个战斗角色使用不同轮廓附件：突击者锐角翼/枪线、控制者核心环、前卫盾面与炮手炮口。
- 所有高威胁动作遵循“预警 → 位移/发射 → 恢复”三段节奏；预警至少 0.25 秒，并通过颜色、形状而非只靠闪白区分。
- 同屏协同截图应能同时看出站位层级、攻击主次和安全逃生方向，不允许敌人、奖励或平台重叠。

## 本批边界

13C 完成敌人职责、攻击多样性和同屏调度，不在本批全面重做所有 50+ 目标敌种。命中停顿、材质音效、镜头震动与全技能特效的统一深化归 13D；长期难度曲线仍需策划试玩后调整。
