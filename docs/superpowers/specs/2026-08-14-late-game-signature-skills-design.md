# 六武器后期招牌技能质变设计

**日期：** 2026-08-14  
**范围：** 阶段 13.4.2，装备与技能系统继续完善  
**目标：** 在不破坏旧存档和现有输入体系的前提下，让六类武器各自的后期技能具备清晰、强烈且可辨识的商业级招牌表现。

## 1. 设计原则

- 本批不堆叠大量同质节点，优先把现有后期技能做出“前期技能升级后发生质变”的体验。
- 每种武器选择一个已存在的后期技能作为招牌技能，保持技能 ID、前置节点、解锁等级和存档数据兼容。
- 所有招牌技能统一采用五阶段节奏：蓄力预警、角色位移或主体释放、多段命中、终段爆发、残留与收招。
- 特效必须服务于判定：危险方向、攻击范围、命中时刻和残留区域均需可读，不能用不透明粒子遮住角色、敌人和平台。
- 后期技能允许更强的命中停顿、震屏、镜头聚焦与短暂时间缩放，但必须设置强度上限，避免连续命中造成眩晕或操作丢失。

## 3. 表现架构

### 3.1 数据层

在技能数据中为六个招牌技能补充统一的 `showcase_profile`：

- `palette`：主色、辅色、核心白闪色。
- `telegraph_shape`：直线、圆环、牢笼、准星等预警形态。
- `motion_style`：残影冲刺、磁轨飞行、后坐蓄力、螺旋钻突等角色/武器运动。
- `impact_style`：剑痕引爆、熔核震环、压力核爆、交叉刃、齿轮龙卷、箭雨汇聚。
- `residue_style`：短暂电弧、熔渣、蒸汽雾、裂隙碎片、旋转齿轮、标记余辉。
- `camera_grade`：`signature` 或 `ultimate`，由统一预算换算为镜头反馈。

旧字段 `preview_pattern`、`preview_intensity` 和 `preview_stages` 保留；新字段缺失时继续走现有表现，保证旧技能与旧存档兼容。

### 3.2 预览层

扩展 `skill_preview_effect.gd`，在现有五阶段预览中加入：

1. 明确预警范围和方向；
2. 主角、武器或投射物的可见运动轨迹；
3. 至少两个可辨识的中段命中节拍；
4. 面积和亮度明显高于中段的终段爆发；
5. 逐渐衰减的残留效果与清晰收招。

技能树右侧预览必须完整循环，不依赖角色已解锁技能或玩家存档，不产生真实伤害、掉落或保存操作。

### 3.3 实战层

实战继续使用现有主动技能和武器释放框架。新增统一的招牌视觉编排器，只接收技能 ID、朝向、命中位置和阶段事件，不重新实现伤害判定。这样视觉表现不会与实际命中逻辑分叉。

反馈预算：

- 中段命中只使用轻至中档顿帧和震屏；
- 最终命中才允许终结档白闪、镜头聚焦和强震屏；
- 同一技能的镜头事件在 90 ms 内合并；
- 全屏白闪透明度不超过现有可读性上限；
- 时间缩放只用于最终爆发，持续时间短于收招窗口。

## 4. 装备与技能界面联动

- 装备仓库中六种武器的详情增加“招牌后期技能”一行，显示技能名称和解锁状态。
- 已解锁招牌技能使用武器专属色；未解锁显示前置节点名称，不泄露错误输入提示。
- 技能树选择招牌技能时，右侧标题增加“招牌技”标记，展示完整组合输入、用途、成长、前置和五阶段演示。
- 不增加新的装备槽、货币或材料，避免本批扩大为装备养成重构。

## 5. 兼容与失败处理

- 不修改六个现有技能 ID，不重命名武器 ID，不改变存档版本字段。
- `showcase_profile` 解析失败或字段不完整时回退到 `preview_pattern`。
- 预览节点、假人或效果实例缺失时记录明确错误，但不得写入玩家存档。
- QA 截图使用独立输出目录，不覆盖策划素材或用户现有文件。

## 6. 验收标准

- 六种武器各有一个可辨认、互不混淆的后期招牌技能演示。
- 每个演示均能从连续 PNG 中识别五阶段，最终爆发明显强于中段命中。
- 装备详情能显示对应招牌技能及解锁状态。
- 旧技能数据、旧装备、旧存档迁移与全部既有测试继续通过。
- Godot Capture 至少抓取六组、每组八帧实际 PNG，并逐张目视检查。
- 编辑器解析、全部测试、主场景运行和发布版运行均无可执行 `ERROR` / `SCRIPT ERROR`。
- QA 记录写入 `docs/qa/13.4.2-review.md`，更新 `docs/DEV_PLAN.md`，导出 EXE + PCK 并提交 Git。

## 7. 明确不在本批范围

- 不新增第七种武器。
- 不重做伤害公式、技能点经济或完整装备锻造系统。
- 不下载外部素材；本批效果优先由程序化图形、现有角色/武器投影和统一反馈层构成，因此没有新增许可证记录。
- 不把阶段 14 的手柄重绑与多分辨率工作提前混入本批。
