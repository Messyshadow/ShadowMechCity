# 阶段 11　四大特色系统总设计

> 状态：设计定稿与开发准备，未实现　　日期：2026-08-20

## 1. 设计目标

四个系统共同表达「暗影机械城」的核心特色：玩家不只收集装备和技能，还能管理机械伙伴、远程改造硬件、攻击敌人代码，并将战场暂时折叠进虚拟量子空间。

开发原则：

- 一次只实现一个可玩垂直切片，每步都能独立测试、发布和回退。
- 四系统通过稳定 ID 和事件协议联动，不直接互相操作场景内部节点。
- 先保证玩法可读、可控和存档安全，再增加大量机器人、品牌和视觉变体。
- 不覆盖现有技能、装备强化、敌人 AI 或存档，在原系统上迁移扩展。

## 2. 四系统的关系

```text
敌方机器人 ─黑客临时控制→ 战场友军（不跟随、不持久化）
      └量子战斗空间收录→ 机器人档案库 → 活动空间培养 → 召唤阵容

玩家装备 ─卫星量子补丁→ 属性/词缀/外观版本
召唤、黑客、量子空间 ─技能树节点→ 容量、效率、风险和功能
```

「黑客临时征用」与「量子永久收录」必须是两套状态：前者仅改变当前战斗的阵营和 AI，后者写入持久化机器人档案。

## 3. 11.1 机器人召唤系统

### 核心体验

- 完成「量子模块激活」后获得一台初始机器人。
- 初始只能同时召唤 1 台；技能升级后扩展到 2 台、最多 3 台。
- 同一机型不能重复上阵，但可在阵容中混合空中与地面机器人。
- 空中类包含炮击、侦察、干扰或治疗定位；地面类包含近战、盾卫、爆破或狙击定位。
- 机器人拥有独立 HP、技能冷却和损毁后重构时间；离玩家过远时安全量子回收，避免卡地形。

### AI 状态与平衡

`STORED → DEPLOYING → FOLLOW ↔ ENGAGE → RECALLING / DISABLED`

- 只攻击玩家已拉仇恨或正在伤害玩家的敌人，不应跨屏开怪。
- 召唤物不消耗敌人战斗导演的攻击令牌，但自身应有联动冷却，避免三台同时爆发。
- 三台合计持续输出初期以玩家持续输出的 35% 左右为调试基线，辅助机器人将输出换成控制、保护或恢复价值。

### 子步骤

1. **11.1a 单召唤垂直切片**：机器人档案、存档迁移、一台默认地面机器人、召唤/回收、HUD 冷却和一个实战房。
2. **11.1b 空中/地面差异**：至少两种空中和两种地面定位，补齐索敌、跟随、防卡位和角色剪影。
3. **11.1c 多槽阵容**：技能点解锁 2/3 槽，阵容 UI、不同型号校验、协同攻击与量子超载。
4. **11.1d 视觉与平衡**：召唤投射、回收、损毁、技能预警特效，同屏性能和 Boss 战压力测试。

11.1 不等待 11.4 才可玩：先给旧存档和新档一个初始档案。11.4 上线后直接复用同一 `robot_instance_id` 数据库。

## 4. 11.2 装备量子升级系统

### 世界观与玩法

不同企业为武器、防具和饰品提供「卫星储能量子投射」服务，把固件补丁、主题和个性化配置直接写入硬件。这是一个游戏内金币消耗系统，不是真实货币订阅或付费服务。

- 沿用现有 `Game.coins`，UI 可在世界观中称为「齿轮币」，不另造第二套钱包。
- 沿用现有装备 `lv` 强化数据，将其迁移为品牌补丁的基础阶段，不清零玩家已强化装备。
- 每件持久装备增加稳定 `item_instance_id`、`brand_id`、`quality`、`patch_level`、`patches`和 `cosmetic_id`。
- 费用由品质、当前阶段和补丁稀有度共同决定；强化前必须预览变化值，高价升级需要二次确认。
- 品牌影响可选词缀池、外观和套装倾向，不应让玩家因为混搭品牌而无法通关。

初始品牌可使用：铸魂工坊（近战/破防）、虚空蒸汽局（远程/控场）、深渊腐化所（持续伤害）、遗迹符文院（护盾/反弹）和量子虚空研究所（暴击/吸血）。

### 子步骤

1. **11.2a 数据迁移与报价**：稳定装备 ID、品牌/品质/补丁数据、纯函数费用与属性预览，保留旧 `lv`。
2. **11.2b 量子升级台**：枢纽 NPC/终端、分类界面、卫星投射演出、确认/取消与存档。
3. **11.2c 个性补丁**：可替换词缀、外观主题和音效主题，将战力向与外观向成本分开。
4. **11.2d 品牌套装**：二件/四件效果、属性解析器接入、极端搭配和旧存档回归。

## 5. 11.3 黑客入侵系统

### 核心能力

- **核心腐化**：持续伤害或降低机械防御。
- **临时征用**：在原地改为友军并攻击周围敌人，不跟随玩家，时间结束后恢复敌对或安全关机。
- **混乱指令**：随机选择战场单位攻击，包含其原阵营，但不能伤害剧情 NPC。
- **系统过载/数据窃取**：延时爆破或获取经验/档案数据。

成功率必须同时考虑黑客技能等级、玩家与目标等级差、目标当前 HP 和目标网络防护级别。对明显高级目标失败时可触发电磁反噬，UI 必须在确认前显示概率档位与反噬风险。

限制：

- 只有具备 `hackable` 能力标签的机械目标可入侵，生物、剧情角色和环境装饰不可入侵。
- Boss 只允许白名单效果（如核心腐化、数据扫描），不允许改变阵营、混乱、即死或爆破。
- QA 可用固定随机种子或强制结果钩子验证成功/失败/反噬，正常游戏仍使用真实概率。

### 子步骤

1. **11.3a 入侵协议**：可入侵标签、纯成功率函数、目标选择、风险 UI、反噬伤害事件。
2. **11.3b 腐化与临时征用**：状态叠加、阵营暂时覆盖、回复规则与战斗导演兼容。
3. **11.3c 混乱/过载/窃取**：补齐效果、高阶技能树与 Boss 白名单。
4. **11.3d 反制与教学**：高级敌人防火墙预警、反入侵攻击、音视觉反馈和难度曲线。

## 6. 11.4 虚拟量子空间

### 活动空间

- 仅在非战斗状态开启；角色进入独立 2D 横版场景，主世界暂停并保留返回点。
- 机器人可自由活动，玩家可查看档案、调整最多三台召唤阵容、投放强化芯片、学习技能和修复。
- 空间可分层扩展，但首版只实现一个有完整功能的活动层；容量和后续层数用数据扩展，不在首版复制空房间。

### 战斗空间

- 战斗中开启局部 `Area2D` 量子泡，不暂停主场景；有能量消耗、持续时间和冷却。
- 环境加点可降低敌人移动/攻击/弹幕速度，或增加玩家镜像；效果只作用于量子泡内。
- 强敌的有效控制时间更短；低血量、低等级和普通级机器人更容易收录。
- 每个目标每次量子泡只允许尝试收录一次，避免无成本连点刷概率。

### 收录边界

- 可收录目标必须同时具备 `robotic` 与 `capturable` 标签。
- 剧情 NPC、有机生物、召唤物、临时分身和唯一 Boss 不可永久收录。
- 若未来需要「Boss 投影」，应作为单独的弱化复制体奖励，不移除世界 Boss，不修改 Boss 击杀事实。

### 子步骤

1. **11.4a 活动空间首层**：进入/退出、战斗阻止、机器人自由活动、档案与阵容管理。
2. **11.4b 培养**：芯片、修复道具、技能数据盘、经验/亲和度与存档。
3. **11.4c 战斗量子泡**：局部环境效果、时长/冷却、强敌抗性与清晰边界。
4. **11.4d 机器人收录**：低血量/等级差/强度概率、单泡尝试限制、容量处理与召唤联动。

## 7. 公共数据与存档

新存档字段必须有默认值并通过新版本迁移器幂等补全：

```text
robot_roster: [{robot_instance_id, model_id, level, xp, learned_skills, upgrades, affinity}]
summon_loadout: [robot_instance_id, ...]
summon_slot_level: 1..3
equipment patches: item_instance_id + brand_id + quality + patch_level + patches + cosmetic_id
hacking: {unlocked, protocol_level, learned_nodes}
quantum_space: {unlocked, living_floor, capacity, learned_nodes, cooldown_state}
```

不存储场景节点路径、运行时 instance ID、背包数组下标或正在进行的短暂 AI 状态。随机入侵/收录的临时 QA 种子不写入正式存档。

## 8. UI 与技能树接入

- 召唤、黑客和量子空间作为现有圆形技能矩阵的扩展页/分支，沿用鼠标与 WASD/方向键、双环高亮和右侧动画详情。
- 装备补丁从背包装备详情或枢纽升级终端进入，不塞进战斗技能树。
- 概率操作要显示「安全/可行/高风险/极危险」档位，可显示精确数字，但不能在失败后偷改概率。
- 召唤物的生命、冷却和指令状态应放在紧凑 HUD，三台同时上场不得遮挡玩家生命、任务跟踪或 Boss 血条。

## 9. 每个子步骤的验收门槛

1. 先有失败契约，再实现代码。
2. 新老存档迁移反复运行不丢字段、不重复奖励、不降级。
3. 至少覆盖正常状态、失败/拒绝状态、升级后状态和极限状态。
4. 扫描全部 `ERROR` / `SCRIPT ERROR`，运行主场景和新系统实战房。
5. 用 `godot-capture` 生成实际 PNG 并逐张查看；对概率或 AI 行为使用确定性 QA 钩子进入指定状态。
6. 在 `docs/qa/` 写验收报告，更新计划，用项目指定的源码 Godot release 模板导出，验证发布版后再提交。

## 10. 已解决的设计冲突

- **召唤先做、量子仓库后做**：11.1 先创建稳定的初始机器人档案，11.4 只扩展管理与收录入口，不二次迁移。
- **Boss 收录与世界进度**：首版 Boss 不可永久收录；可扫描数据或获得弱化投影奖励，不删除 Boss 实体或任务事实。
- **已有强化与新补丁系统**：现有 `lv` 成为新 `patch_level` 的迁移输入，不再并行维护两套强化等级。
- **黑客友军与收录伙伴**：黑客不写入机器人档案，量子收录才能生成永久 `robot_instance_id`。

## 11. 明日建议开工点

从 **11.1a 单召唤垂直切片** 开始。这一步只做一台初始地面机器人的数据、存档、召唤/回收、基础 AI、HUD 和一个可重复验证的战斗场景。不在同一批次开始三召唤、黑客、装备补丁或量子收录。
